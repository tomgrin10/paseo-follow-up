# Paseo Follow-up

Trusted Paseo plugin with separate client, server and shared boundaries. Minimum Paseo is 0.14.0. Use native React Native controls and host theme tokens.

The public name is Follow-up and the npm package is paseo-follow-up. Retain installation id follow-through, RPC names and plugin-data/follow-through for existing installations. Never reset tracked work or settings during an upgrade.

Never commit credentials, daemon state, transcripts or local machine paths. Boolean configuration uses positive enable_ names. Subprocesses use argument arrays without a shell.

The optional Send to Paseo integration uses only `follow.pr-owner` and the scoped browser exchange.
Record the latest explicit registering agent on each PR; legacy registrations retain their workspace
main. Browser exchange defaults to no repository scopes. Unknown toggle state never means off.

Run npm run verify, npm run test:install and npm pack --dry-run. Integration checks use isolated Paseo/provider homes and synthetic agents. Never restart the user's daemon or send test messages into real conversations.

Server MCP and hook source files are generated by scripts/build.mjs. Include generated output when changing their scripts. All button settings live in the host-scoped Display preferences and preserve older saved sidebar values.

Publish from a clean main with matching package/lock versions and an immutable vX.Y.Z tag. The npm workflow uses Trusted Publishing; never move a published tag. Wait for registry integrity verification before claiming npm publication. See README.md for setup and OVERVIEW.md for data access and automation boundaries.

PR submission discovery uses completed shell-tool receipts from workspace root sessions, never a
repository-wide worktree scan or plain PR mentions. Constrain receipts by the workspace project’s
GitHub repository identity; preserve explicit registrations, exclusions and existing owners. Root
contributors get PR status/registration/sync only; goal/task/scope/completion authority stays with
the recorded main agent. Tests must cover secondary worktrees and an unavailable recorded owner.

A parent-agent label alone does not identify a workspace subagent. Resolve the parent’s workspace:
launches into a different workspace are eligible local roots; same-workspace children stay excluded.
Use server/workspace-agent.ts consistently for discovery, tool access and recovery handoff. Unknown
parent membership must not grant new scope. Cover workspace-first agent creation in packed tests.
